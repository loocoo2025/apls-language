# APLS 0.1 使用教程

> 适用版本：`APLS-0.1-BASELINE-001`（精确 Commit `fd8b59536fcdfdff2f3b199b882c15d97edb1993`）
> 语言 Profile：`apls-zh-CN-0.1`（简体中文受控自然语言）
> 依据：`04_design/language/APLS_0.1_ZH_CN_LANGUAGE_PROFILE.md`、`APLS_0.1_ZH_CN_GRAMMAR.ebnf`、`04_design/compiler/APLS_0.1_COMPILER_MVP_DESIGN.md` §7～§8

---

## 1. 这是什么

APLS 是一门**声明式软件规格语言**：你用受控的简体中文句子描述"系统里有什么、什么情况下必须做什么"，编译器把它转换成唯一确定的机器契约（Canonical IR），供 AI Agent 直接消费。

核心承诺只有一条：

> **同一合法输入只有一个规范化解释。无法证明唯一时，编译器必须拒绝并给出诊断，绝不猜测。**

所以使用这门语言的心法是：**写确定的句子，而不是写"差不多能懂"的句子。**

## 3. 四条命令

```text
apls parse <entry.apls>                                    # 只解析
apls check <entry.apls>                                    # 解析 + 全部语义检查
apls emit-ir <entry.apls> --output <path|->                # 生成已验证的 Canonical IR
apls diagnose <entry.apls> [--through parse|check|emit] [--format json|human]
```

| 退出码 | 含义 | 你该怎么做 |
|---:|---|---|
| `0` | 成功 | 继续 |
| `1` | 你的 Source 被诊断拒绝（`APLS-E...`） | 读诊断，改句子 |
| `2` | 工具失败（`APLS-T...`：路径、I/O、资源超限等） | 检查文件路径/输入规模；**不是你的语义错误** |
| `3` | 编译器内部失败 | 不应发生；发生即为编译器缺陷，请报告 |

日常用法：

```bash
apls check my_spec.apls                    # 写完先检查
apls diagnose my_spec.apls                 # 失败了？看机器可读诊断（默认 JSON）
apls diagnose my_spec.apls --format human  # 或者人类可读
apls emit-ir my_spec.apls --output ir.json # 通过后产出 IR
```

**重要**：只有 `emit-ir` 以退出码 `0` 结束，`--output` 里的内容才是有效 IR。任何失败都不会产生部分结果文件。

## 4. 文件规则（先记这六条，能避开 80% 的拒绝）

1. 文件必须是 **UTF-8、无 BOM、已是 NFC 正规化**（编译器不会帮你正规化）；
2. 每句以全角句号 `。` 结尾；从句分隔用全角逗号 `，`；**不接受 ASCII 标点**；
3. 术语定界用 `“”`，说明文本定界用 `『』`；引号不嵌套、不跨行；
4. 空白只允许空格和换行，**禁止 Tab**；
5. **首句必须一字不差**是：

```text
本规范采用 APLS 简体中文语言版本 0.1。
```

6. 一个文件就是一份完整规范（0.1 只有单入口 Source，没有 import）。

## 5. 十分钟写出第一份规范

以"水箱液位低时启动灌溉水泵"为例，完整可编译（已用 Baseline 编译器实测：`check` / `emit-ir` 均 Exit 0）：

```text
本规范采用 APLS 简体中文语言版本 0.1。

“水箱液位”是百分比类型的可观测属性。
“灌溉水泵”是设备。
“启动”是“灌溉水泵”支持的动作。
“停止”是“灌溉水泵”支持的动作。
“急停”是组件。
“急停”的状态包括“未激活”和“激活”，初始状态是“未激活”。
“急停命令”是事件。
“灌溉水泵”的状态包括“停止”和“运行”，初始状态是“停止”。
“启动命令”是事件。

当水箱液位低于 20% 时，系统必须启动灌溉水泵。
急停处于激活状态时，系统禁止启动灌溉水泵。
当系统收到急停命令时，急停从未激活状态进入激活状态。
当系统收到启动命令时，灌溉水泵从停止状态进入运行状态。
安全要求：急停处于激活状态时，灌溉水泵必须处于停止状态。
验收要求：当系统收到启动命令时，灌溉水泵处于运行状态必须在 2 秒内成立。
说明：『本规范适用于温室灌溉演示场景』。
```

编译产物 IR 包含：2 实体、1 属性、2 动作、2 事件、2 状态机、2 规则、2 转换、1 安全不变量、1 验收要求、1 说明项。

### 5.1 写作顺序

**先声明，后使用。** 每个概念都要先用声明句"登记"：

| 你要表达 | 句式 | 例子 |
|---|---|---|
| 一个东西存在 | `“X”是设备/组件/传感器/执行器。` | `“灌溉水泵”是设备。` |
| 一个可观测/可写的量 | `“X”是T类型的可观测属性。`（可见性：`可观测`/`可写`/`可观测且可写`） | `“水箱液位”是百分比类型的可观测属性。` |
| 一个动作 | `“X”是“实体”支持的动作。` | `“启动”是“灌溉水泵”支持的动作。` |
| 一个事件 | `“X”是事件。` | `“启动命令”是事件。` |
| 一个别名 | `“X”是动作“Y”的别名。` | `“打开”是动作“启动”的别名。` |
| 一个自定义单位 | `“X”是单位。` | `“升每分钟”是单位。` |
| 状态机 | `“E”的状态包括“S1”、“S2”和“S3”，初始状态是“S1”。` | 见上例 |

注意：

- 名称在各自类别内唯一；`系统` 是内建 Actor，不要声明它；
- 带单位的属性要写 `，单位为“…”`（自定义单位需先声明）；**百分比值必须带 `%`，时长必须带 `毫秒/秒/分钟`，温度必须带 `摄氏度`**——编译器不会替你猜单位；
- 声明顺序无所谓，前向引用合法（编译器做两阶段处理）。

### 5.2 写行为规则

三种引导形式**完全等价**，任选：

```text
当水箱液位低于 20% 时，系统必须启动灌溉水泵。
如果水箱液位低于 20%，系统必须启动灌溉水泵。
水箱液位低于 20% 时，系统必须启动灌溉水泵。
```

禁止用 `不得` 或 `禁止`（两者同义）：

```text
急停处于激活状态时，系统禁止启动灌溉水泵。
```

**一句只能有一个模态和一个动作。** 两个义务就拆成两句，不能用"并且"连动作。

### 5.3 条件怎么写

条件只有三种原子形式，可用 `并且` 平铺合取：

```text
水箱液位低于 20%                # 属性比较
急停处于激活状态                # 状态条件
系统收到启动命令                # 事件条件
```

可用比较词（封闭集合）：`等于、不等于、低于、不高于、高于、不低于`
可用模态词（封闭集合）：`必须、不得、禁止`

`应该、最好、尽快、适当` 等词**没有规范含义，会被拒绝**。

### 5.4 状态转换、安全不变量、验收

```text
当系统收到启动命令时，灌溉水泵从停止状态进入运行状态。

安全要求：急停处于激活状态时，灌溉水泵必须处于停止状态。

验收要求：当系统收到启动命令时，灌溉水泵处于运行状态必须在 2 秒内成立。
```

- 转换的源/目标状态必须属于同一实体且已在状态声明中列出；
- **每个声明的状态都必须能从初始状态沿转换图到达**，否则被拒绝（E1402）——写了状态就要给它写转换路径；
- 状态声明的列表分隔用 `、`，最后两项用 `和`；至少两个不同状态；源状态与目标状态不能相同（E1404）；
- `安全要求：` 前缀才建立安全不变量——普通规则不会因为"看起来重要"自动升级；
- 验收必须给出确定时限；`立即`、`尽快` 不合法；
- 同一实体、同一源状态、同一触发条件下指向两个不同目标状态会被拒绝（E1403）；相同条件下对同一动作同时"必须"和"禁止"会被拒绝（E1405）。

### 5.5 说明句（不写进语义）

```text
说明：『本规范适用于温室灌溉场景，水量单位为升』。
```

说明句同样以 `。` 收尾（句号在 `』` **之后**）。说明只进 IR 的 informative 区，不建立任何术语、约束或行为。

## 6. 术语引用：裸写还是加引号？

正文里两种都行：

```text
当水箱液位低于 20% 时，系统必须启动灌溉水泵。      # 裸引用
当“水箱液位”低于 20% 时，系统必须启动“灌溉水泵”。 # 精确引用
```

编译器会枚举裸引用的所有可能切分，**只要最终收敛到唯一语义就接受**——你不需要因为"可能有多种切法"而加引号。只有当编译器报 `APLS-E1310`（AMBIGUOUS，存在两个以上不等价解释）时，才需要你消歧，加引号精确引用是手段之一。

## 7. 被拒绝了怎么办：诊断速查

```bash
apls diagnose my_spec.apls --format json
```

输出是机器信封（Envelope），`status` 为 `accepted/rejected/tool_failure/internal_failure`；每条诊断有稳定 Code 和精确 Span（行从 1 起，列按字符数）。**根因看 Code，不要依赖英文消息文本。**

常见拒绝与对策：

| 现象 | 典型 Code | 对策 |
|---|---|---|
| 句子无法解析 | `E1101` | 对照本教程 §5 的句式；检查是否用了未登记句式或 ASCII 标点 |
| 术语未声明/多候选 | `E1201/E1202` 等 | 先写声明句；或加引号精确引用 |
| 缺单位/单位不匹配 | `E1308` 等 | 百分比带 `%`，时长带 `秒/分钟/毫秒`，温度带 `摄氏度` |
| 模糊量词（高/低/尽快…） | `E1301` 等 | 改成确定数值与比较词 |
| 指代（它/该设备…） | `E1302` 等 | 写出完整术语名，每句自包含 |
| `或者`/并列义务 | `E1305` 等 | 拆成多句；`并且` 只能连条件 |
| 状态从初始状态不可达 | `E1402` | 为该状态补转换路径，或从状态列表移除 |
| 转换的源/目标状态相同 | `E1404` | 状态转换必须改变状态 |
| 同条件同动作既"必须"又"禁止" | `E1405` | 消除规则冲突——0.1 不做优先级裁决 |
| 多个不等价解释 | `E1310` | 按诊断给出的分歧角色补充信息或加引号 |
| 资源超限 | `T0007`（Exit 2） | 输入超过固定上限；这不是歧义报错，拆分/精简输入 |
| 非 NFC / 非法字符 | `E1004` 等 | 用编辑器转为 NFC、去 BOM、去 Tab |

## 8. 推荐工作流

```text
写句子（§5 句式）
  → apls check          # Exit 0？
  → 否：apls diagnose   # 按 Code 修句子，回到上一步
  → 是：apls emit-ir --output spec.ir.json
  → 把 spec.ir.json 交给 Agent / 下游工具消费
```

你**不需要**看懂 IR；它是机器契约。需要人工核对语义时用 `apls diagnose` 的输出和规范句本身。

---

## 9. 0.1 明确不支持（不要踩）

- 英文或中英混合句法；自由自然语言（只能放在 `说明：『…』` 里）；
- `或者`、括号嵌套条件、多层否定、跨句指代、主语省略；
- 通用写入行为（`set` 是保留字，0.1 没有可变数据模型）；
- 多文件 import（单入口 Source）；
- 单位换算推断（自定义单位是名义单位，编译器不猜换算关系）；
- 任何形式的"编译器帮你猜"：没有最长匹配、概率、AI 消歧。
