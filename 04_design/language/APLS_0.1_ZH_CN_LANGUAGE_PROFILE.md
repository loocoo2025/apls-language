## 1. Profile 范围

APLS 0.1 只定义一套规范性简体中文语法结构。领域术语可以含汉字、ASCII 拉丁字母、ASCII 数字及少量已列出的连接字符，但这不构成英文或中英混合语法支持。

```text
规范中文句式 + 已声明领域术语 -> 可进入编译
英文句式或未登记句式           -> 拒绝
自由自然语言                   -> 只能作为 AI 草拟输入或说明文本
```

用户只需编写受控中文句子。Semantic Frame、AST 和 Canonical IR 默认不可见。

## 2. Source 字符与文件规则

### 2.1 编码

- Source 必须是有效 UTF-8，禁止 BOM；
- 禁止孤立代理码、非字符码位和 Unicode 控制字符；
- 允许的结构空白只有 U+0020、LF 和 CRLF；禁止 Tab、CR 单独出现和其他 Unicode 空白；
- 编译器保存原始 Byte，所有 Span 使用零起点、半开 Byte 区间；
- Source 必须已经是 Unicode NFC；编译器不得静默正规化，非 NFC 输入直接拒绝；
- Profile 的 Unicode 数据版本固定为 `17.0.0`，Normalization 固定为 `NFC`；公开机器声明只位于 CNL IR Header，Compiler Binary 以同版本常量和构建/启动断言绑定该 Profile，不另设 Compiler Manifest，也不改变既有 `apls --version` 格式。同一 Compiler Version 内不得变化。完整算法与依赖候选见 `DES-APLS-CNL-UNICODE-001`。

### 2.2 规范标点

- 规范句必须以全角句号 `。` 结束；
- 从句分隔只使用全角逗号 `，`；
- 术语定界使用左双引号 `“` 与右双引号 `”`；
- 说明文本定界使用 `『` 与 `』`；
- 不接受 ASCII 句号、逗号或直引号作为等价替代；
- 引号不得嵌套，不得跨越换行，左右引号必须成对。

空格和换行只允许出现在 Grammar Token 边界，不得拆开一个固定关键词、数值或术语名。允许位置上的空白不改变语义。

### 2.3 句子类别

Source 只包含三类句子：

1. Profile 声明；
2. 术语/结构声明；
3. 规范性行为句或显式说明句。

首句必须是：

```text
本规范采用 APLS 简体中文语言版本 0.1。
```

说明句采用：

```text
说明：『此处内容不改变规范语义』。
```

说明文本只进入 informative 区，不建立术语、默认值、约束或行为。

## 3. 术语系统

### 3.1 声明名

每个领域概念必须先在某个声明句中用 `“名称”` 建立。术语名：

- 长度为 1～64 个 Unicode Scalar Value；
- 第一个字符必须是基本汉字、扩展 A 汉字或 ASCII 字母；
- 后续字符只允许基本汉字、扩展 A 汉字、ASCII 字母、ASCII 数字、`_`、`-` 或 `·`；
- 不允许空白、句法标点、引号或控制字符；
- 按 NFC 后的 Unicode Scalar 序列区分大小写并精确比较；
- 不进行繁简转换、拼音匹配、词干化、近似匹配或常识同义推断。

“简体中文 Profile”约束的是句法关键词；术语名中的 `CAN总线`、`RTK定位器` 等领域缩写是合法名称。

### 3.2 唯一名称

- 实体、属性、动作、事件和单位在各自符号类别内名称唯一；
- 状态名在所属实体内唯一，不要求跨实体唯一；
- 相同显示名跨类别出现时，只有 Grammar 角色能唯一确定类别才可接受，否则拒绝；
- 别名必须显式声明，在目标的类别与作用域内唯一，且一个别名只能指向一个目标；
- `系统` 是 Profile 内建 Actor，禁止重新声明或作为别名；
- 固定关键词和完整固定短语不得作为声明名。

### 3.3 引用形式

正文允许两种引用：

```text
水箱液位
“水箱液位”
```

带引号引用按完整名称精确查找。裸引用由术语索引枚举所有可能切分，并结合 Grammar 期待的符号类别构造候选。中间可以存在多个完整 Token 序列和 Parse；全部有效候选经过语义绑定、检查与规范化后，只要收敛为一个 Canonical Frame 等价类就必须接受。

禁止用“最长匹配优先”、声明顺序、概率或第一个成功分支静默消除候选。只有最终仍存在两个及以上不等价 Canonical Frame 时才以 `AMBIGUOUS` 拒绝；带引号精确引用是用户缩小候选的一种方式，不是中间多切分本身触发的强制要求。

### 3.4 声明 Bootstrap 与两阶段处理

Declaration Pass 不得依赖尚未建立的 Terminology Graph。唯一允许的启动算法是：

1. Unicode/Sentence Validator 先冻结 Sentence Span；Profile Declaration 单独按固定 Production 解析；
2. 对其余每个 Sentence 执行 `declaration_bootstrap`：Lexer 只识别固定字面量、数值和满足第 3.1 节的带引号 `DECLARED_TERM`，不得为其猜测实体/属性/动作/事件/状态/单位类别；
3. 所有完整 Bootstrap Token Stream 都调用同一份正式 Grammar 的 `declaration-sentence` Entry；它不是正则、手写或第二规范 Parser。声明 Production 中的引用也暂存为无类别的带引号名称，并由所在 Production 给出 Expected Category Role；
4. 收集所有成功的 Declaration Syntax Candidate 后，先从 Root Production 建立全部 Provisional Header，再统一解析类别、Owner、别名、重复项和前向引用；只有所有声明候选完成确定绑定、等价候选收敛且无公共 Error，Terminology Graph 才可冻结；
5. 没有成功 Declaration Candidate 的 Sentence 进入 Normative Pass，由冻结后的 Terminology Graph 产生全部 category-labelled `EXACT_*_REF/BARE_*_REF` Edge，再调用同一正式 Grammar 的对应行为 Entry；
6. Declaration 与 Normative Production 的 Source Language 必须不相交；若同一 Sentence 在两类 Entry 都有成功 Candidate，属于 Compiler/Grammar Contract Failure，使用 `APLS-T0006` 失败，不得选择任一类。

声明 Bootstrap 的失败证据在该 Sentence 后续形成有效 Normative Frame 时保持内部；若两类 Entry 最终都没有有效 Candidate，则按 CNL 诊断的零候选聚合规则形成公共错误。任何声明语义错误都会阻止 Terminology Graph 冻结，并阻止行为句进入 Candidate Binding，避免派生级联错误。

因此允许声明内部和行为句的前向引用，声明与行为句的文件顺序不改变名称解析结果。Bootstrap 的 Edge、Stream、Token、Syntax Node、错误归类和资源顺序只按 `DES-APLS-CNL-RESOURCE-001` 计数，不存在不计数的预扫描。

## 4. 内建词汇

### 4.1 类型

首版内建类型：

```text
布尔、整数、小数、百分比、文本、时长
```

### 4.2 单位

首版内建单位：

```text
%、毫秒、秒、分钟、摄氏度
```

百分比值必须带 `%`。时长必须带 `毫秒`、`秒` 或 `分钟`。温度量必须带 `摄氏度`。Property 的类型、声明单位、比较运算符与右值 Literal 只按 `DES-APLS-CNL-SEMVAL-001` 的封闭矩阵组合；表外组合全部拒绝，Compiler 不从领域常识推断默认单位。

### 4.3 比较与模态

比较词只有：

```text
等于、不等于、低于、不高于、高于、不低于
```

规范模态只有：

```text
必须、不得、禁止
```

`不得` 与 `禁止` 在批准句式中映射为同一个 `PROHIBIT` 模态。`应该`、`最好`、`尽快`、`适当`、`通常` 等词不具有规范含义，并在规范句中被拒绝。

## 5. 声明句式

### 5.1 实体

```text
“灌溉水泵”是设备。
“液位传感器”是传感器。
“电磁阀”是执行器。
“控制器”是组件。
```

实体类别固定为：`设备`、`组件`、`传感器`、`执行器`。

### 5.2 属性

```text
“水箱液位”是百分比类型的可观测属性。
“目标流量”是小数类型的可写属性，单位为“升每分钟”。
```

自定义单位必须通过单位声明建立：

```text
“升每分钟”是单位。
```

属性可见性只允许 `可观测`、`可写`、`可观测且可写`。没有 `可写` 的属性不得成为写入目标；APLS 0.1 当前仍不提供通用 `set` 行为。

### 5.3 动作、事件与别名

```text
“启动”是“灌溉水泵”支持的动作。
“停止”是“灌溉水泵”支持的动作。
“启动命令”是事件。
“打开”是动作“启动”的别名。
```

动作声明同时冻结动作名与目标实体的合法配对。别名只能在与目标相同的语法角色中使用。

### 5.4 状态

```text
“灌溉水泵”的状态包括“停止”、“运行”和“故障”，初始状态是“停止”。
```

- 状态列表至少包含两个不同状态；
- 初始状态必须恰好匹配列表中的一个状态；
- 同一实体只能有一个状态声明；
- 列表分隔采用 `、`，最后两项使用 `和`，不得混用其他并列词。

## 6. 条件

首版条件只能是以下原子条件或使用 `并且` 连接的同类平铺合取：

```text
水箱液位低于 20%
急停处于激活状态
系统收到启动命令
灌溉水泵处于“故障”状态
```

规则：

- 一个比较必须包含唯一属性、比较词和有类型值；
- Boolean/Text 只允许等于或不等于；数值类型允许六种比较；完整类型、单位和 Canonical Value 规则见 `DES-APLS-CNL-SEMVAL-001`；
- 一个状态条件必须包含唯一实体和属于该实体的状态；
- 一个事件条件必须包含唯一接收者和事件；
- `并且` 只表示所有原子条件的平铺合取；
- 首版不接受 `或者`、括号、一般自然语言否定或嵌套条件；
- 不接受跨句指代、主语省略、属性所属省略或依赖上下文补全。

## 7. 行为与规则

动作短语由已声明动作和其唯一目标组成：

```text
启动灌溉水泵
“启动”“灌溉水泵”
```

动作与目标必须匹配动作声明。Rule 允许以下三种等价条件引导形式：

```text
当水箱液位低于 20% 时，系统必须启动灌溉水泵。
如果水箱液位低于 20%，系统必须启动灌溉水泵。
水箱液位低于 20% 时，系统必须启动灌溉水泵。
```

它们必须映射到同一个 `Rule` Frame。禁止行为允许：

```text
急停处于激活状态时，系统禁止启动灌溉水泵。
急停处于激活状态时，系统不得启动灌溉水泵。
```

每个规范句只允许一个主模态和一个主行为。多个义务必须拆句，不允许用“并且”连接动作。

## 8. 状态转换、不变量与验收

### 8.1 状态转换

```text
当系统收到启动命令时，灌溉水泵从停止状态进入运行状态。
```

源状态和目标状态必须属于同一实体。`source_state` 本身是 Transition 的隐式前置条件，Source 不需要在 trigger 中重复它。Semantic Checker 必须按 `DES-APLS-CNL-SEMVAL-001` 的有限算法验证显式状态图可达性，以及“同实体、同源状态、同 Canonical Trigger、不同目标状态”的确定冲突；0.1 不猜测一般条件的可满足性或重叠关系。

### 8.2 不变量

```text
安全要求：急停处于激活状态时，灌溉水泵必须处于停止状态。
```

`安全要求：`明确建立 `Invariant` Frame；普通 Rule 不会因措辞看起来重要而自动升级为安全不变量。

### 8.3 验收要求

```text
验收要求：当系统收到启动命令时，灌溉水泵处于运行状态必须在 2 秒内成立。
```

验收句必须给出触发条件、唯一预期条件和确定时限。`立即`、`尽快`、`短时间内` 均不合法。

## 9. 明确拒绝项

下列内容不能进入 APLS 0.1 规范编译：

- 英文句法或中英混合连接词；
- 未在 Grammar 中登记的自由句式；
- “它”、“该设备”、“前者”、“后者”等指代；
- “高”、“低”、“适当”、“一点”、“很快”等未量化表达；
- 未声明同义词、简称或拼写近似；
- `或者`、自然语言括号范围和多层否定；
- 一个句子中的并列义务、并列禁止或多个主 Frame；
- 依赖上一句补足主体、对象、单位、阈值或时限；
- 由 AI、概率分词或运行时置信度选择唯一解释。

## 10. 确定性接受算法

对每个行为句，编译器必须：

1. 枚举所有符合固定词法和已声明术语的 Token 序列；
2. 对每个 Token 序列执行同一正式 Grammar；
3. 为每个完整 Parse 构造候选 Typed Semantic Frame；
4. 依据冻结的类别、角色、绑定、类型和单位规则删除无效候选；
5. 将每个有效候选规范化为 Canonical Frame；
6. 按完整规范结构和语义等价关系建立 Canonical Frame 等价类；
7. 等价类数量为 1 时接受，为 0 时判定非法，为 2 个及以上时判定 `AMBIGUOUS` 并拒绝。

解析器不得用输入顺序、声明顺序、最长词、任意优先级、最高概率、LLM 或第一个成功分支作为选择规则。实现资源不足导致无法穷尽受支持候选时必须报告 Tool Failure，不能伪装为 Source 歧义。

## 11. 目标体验样例

```text
本规范采用 APLS 简体中文语言版本 0.1。

“水箱液位”是百分比类型的可观测属性。
“灌溉水泵”是设备。
“启动”是“灌溉水泵”支持的动作。
“停止”是“灌溉水泵”支持的动作。
“急停”是组件。
“急停”的状态包括“未激活”和“激活”，初始状态是“未激活”。
“急停命令”是事件。

当水箱液位低于 20% 时，系统必须启动灌溉水泵。
急停处于激活状态时，系统禁止启动灌溉水泵。
当系统收到急停命令时，急停从未激活状态进入激活状态。
```

> 本样例已经 Baseline 编译器实测：`apls check` / `apls emit-ir` 均 Exit 0（2026-09-06，DEC-035 修正——原样例缺少指向“激活”状态的转换，会被 E1402 拒绝）。

用户无需因为中间存在多个词法切分或 Parse 而重复引号。只有最终不等价 Canonical Frame 多解时，编译器才要求用户补充信息；显式引用是可选修正手段之一。
